# Doom Health Gathering overfit

A Qwen3.5-4B teacher plays ViZDoom Health Gathering using consolidated history H
and recent history Delta. Descriptor and thinker generate concurrently; the actor
reads stable prefixes and chooses game actions. Qwen3.5-0.8B learns the recorded
trajectory, then controls its own live game. Use the [shared setup](../README.md)
and install the example dependencies:

```bash
uv pip install -e './scripts[notebooks,doom-health]' 'transformers==5.14.1'
```

Open `doom_health_overfit.ipynb` with the project environment as its kernel.
Select one GPU with `CUDA_VISIBLE_DEVICES`. Outputs go to `training_runs/doom_health`;
set `OVERFIT_RUN` to use a fresh directory. Screenshots are generated by ViZDoom;
plots and current results are embedded in the notebook.

`agent.py` implements descriptor/thinker/actor checkpoints and H+Delta updates.
Every three actions Delta is appended to H and cleared. Each selected action
advances the game by four ticks. `environment.py` creates the headless environment
and records scenario hashes; `preflight.py` checks deterministic observations and
the model's image processor. `recording.py` aligns emitted targets to trace rows.

`experiment.py` collects live rollouts, checks inference/replay probabilities,
trains all student parameters including vision, verifies checkpoint reload, and
compares actions, role tokens, frame hashes, health, and game ticks. Evaluation
uses the student's own actions and newly rendered frames. A blank-image control
checks whether the reproduced trajectory depends on visual input.

Defaults: environment seed 105, greedy decoding, at most 12 actions, and up to
80 AdamW updates at `3e-6` in FP32. Replay uses `torch` attention with query chunks
of 64; saved settings apply to parity, training, and reload checks. Cached reports
must match. The allocator limit is 32 GiB. Shared-device use requires explicitly
setting `DOOM_ALLOW_SHARED_GPU=1` and 16 GiB additional free memory beyond that limit.

Run individual stages from the repository root:

```bash
CUDA_VISIBLE_DEVICES=0 uv run --no-sync python -m minisgl_examples.training.doom_health.experiment collect \
  --model Qwen/Qwen3.5-4B --output training_runs/doom_health/teacher.json
CUDA_VISIBLE_DEVICES=0 uv run --no-sync python -m minisgl_examples.training.doom_health.experiment check \
  --source training_runs/doom_health/teacher.json --dtype float16 \
  --output training_runs/doom_health/teacher_parity.json
```

Use each command's `--help` for options. Output files cannot be overwritten.
This is a short same-seed overfit check. Exact trajectory reproduction does not
establish visual dependence when the blank-image control behaves identically.
