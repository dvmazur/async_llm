# Запуск ровера одной командой

Команду выполняйте **в локальном терминале Mac**. Mac должен видеть выбранного ровера
в сети: №80 доступен через `ssh rover`, №107 — через `ssh rover107`.
Также нужен SSH-доступ к серверу `ssh 5.187.77.37`.

```bash
cd /Users/double/Documents/Codex/2026-11-10/x20/outputs
./rover-qwen.sh start --rover 107 --strategy 1 --task "Найди мусорницу" --duration 180
```

Замените `--rover 107` на `--rover 80` для прежнего ровера. Флаг `--rover`
можно ставить до или после `start`; без него сохраняется №80.
Число после `--strategy` выбирает стратегию, текст после `--task` — задание.

| Флаг | Работа стратегии |
| --- | --- |
| `--strategy 1` | Геометрический генератор предлагает кандидатов, Qwen выбирает цель, Nav2 исполняет путь. |
| `--strategy 2` | Qwen генерирует кандидатов по карте и камере, геометрия проверяет их, Qwen выбирает цель, Nav2 исполняет путь. |
| `--strategy 3` | Qwen выбирает ограниченные команды вперёд, влево, вправо и стоп. Между действиями ровер ожидает следующего решения модели. |
| `--strategy 4` | Qwen за один запрос составляет последовательность команд, ровер исполняет её по шагам. `--trajectory-steps N` задаёт верхнюю границу числа действий. |

Если флаг стратегии опущен, используется стратегия 1. `--duration` задаёт бюджет
работы агента в секундах, по умолчанию 180. Подготовка модели происходит перед
этим бюджетом. Сеанс завершается раньше, когда Qwen сообщает о выполнении всей
переданной инструкции. Живой режим не сводит задание к поиску или видимости объекта:
модель учитывает все шаги, условия и последовательность, используя наблюдения,
историю действий, пройденный путь и время. Это оценка модели, а не независимая
проверка успеха. Точность расстояния до распознанного объекта без калибровки
камеры и лидара не гарантируется. Доступные действия определяются стратегией.

Команда автоматически выполняет следующие действия.

1. Подключается к выбранному роверу и запускает существующий контейнер `ros`, если он остановлен.
2. Устанавливает живой агент из серверного репозитория в отдельную папку внутри контейнера:
   `/opt/rover-live` для №80, `/opt/rover-live-107` для №107.
3. Проверяет Qwen3.8-27B-FP8. При необходимости загружает модель на GPU 0 и 1 сервера с TP=2. Для старта нужны свободные GPU.
4. Поднимает live-просмотр и SSH-туннели.
5. Передаёт задание выбранной стратегии и запускает работу ровера.

Код сервера находится в `/home/double/data_scince_expedition/lets/async_llm`.
Инференс выполняется на сервере, обработка сенсоров и движение — на Raspberry Pi,
контроль связи и запуск — на Mac. Оба профиля по умолчанию используют
лидарную одометрию без IMU: на обоих роверах IMU пока присылает нули.
Явный флаг `--imu` включает обязательную проверку аппаратного IMU; применять
его следует после восстановления датчика. При отсутствии измеренной реакции
IMU такой сеанс не разрешит движение.

## Последовательность действий: стратегия 4

Шаблон для команды на Mac после обновления скрипта запуска:

```bash
./rover-qwen.sh start --rover 107 --strategy 4 --trajectory-steps 5 \
  --task "Найди рюкзак и подъедь к нему" --duration 180 --dry-run
```

`--trajectory-steps` принимает целое число от 1 до 32; по умолчанию 5. Это максимум,
а не обязанность заполнить план: модель может завершить его командой `stop` раньше,
когда нужно новое наблюдение. Например: `left, forward, forward, right, stop`.
`stop` заканчивает текущую последовательность, выполнение всего задания оценивается
отдельно по фактическим наблюдениям. Для обычного движения используется тот же
параметр стратегии; `--dry-run` проверяет один ответ без выхода на моторы.

Примитивы такие же, как в стратегии 3: вперёд до 25 см, повороты на 45° на месте.
Для стратегии 4 максимальное время достижения этих величин — 6 секунд вперёд
и 4 секунды на поворот. Исполнение заканчивается по измеренной дистанции или
углу; увеличенный таймаут позволяет медленному приводу завершить шаг.
Во время исполнения новых запросов к LLM нет. Карта, камера, одометрия и защитный
контур продолжают обновляться. Лидар проверяет движение непрерывно, после каждого
действия фактическая поза сверяется с ожидаемой. При препятствии, потере свежести
датчиков или связи, отклонении либо недовыполненном движении остаток плана
сбрасывается. При доступных датчиках и связи следующий запрос получает новое
наблюдение и результат прерванного плана. После потери управляющей связи сеанс
завершается по прежним правилам.

Линия плана на карте показывает **номинальные** положения после команд; это
предсказание, а не гарантированно проходимый путь. В журнале `events.jsonl` события
`trajectory_started`, `trajectory_step`, `trajectory_finished` сохраняют исходный
план, фактические результаты шагов и отброшенный остаток. Ответы модели содержат
`actions`, `trajectory_steps`, `step_probabilities`. Стратегии 1–3 сохраняют прежние
интерфейсы. IMU, как и раньше, отключён по умолчанию.

Промпты всех живых стратегий находятся в `candidate_nav/task_policy.py`.
Для стратегии 4 используются `TRAJECTORY_SYSTEM`, `TRAJECTORY_SPATIAL_PROMPT`,
а также общие `OBSERVER_PROMPT`, `COMPLETION_PROMPT` и `TASK_RULES`.
Формат ответа ограничивается в `candidate_nav/llm.py`: допустимы только F/L/R/S,
не больше заданного количества, после S генерация прекращается. План не выдаётся
исполнителю до завершения генерации всех его действий. Оценки вероятностей
показывают распределение по разрешённым буквам, а не вероятность успешного проезда.

## Если ровер стоит и меняются статусы Qwen

В стратегии 2 генерация и выбор — отдельные вызовы модели. В разделе навигации
теперь показано, сколько точек Qwen прошло проверку. Если карта блокирует старт,
сайт показывает причину и запас известного свободного пространства у центра.
При полностью недостижимом старте генерация точек пропускается: карта продолжает
обновляться, модель проверяет выполнение задачи, а движение ждёт проходимого
старта. Это ожидание не означает, что задача выполнена.

После отклонения координат их причины возвращаются Qwen в следующем запросе.
Кандидаты стратегии 2 по-прежнему создаёт модель; автоматической подмены
геометрическими кандидатами нет.

## Проверка без движения

```bash
./rover-qwen.sh start --rover 107 --strategy 2 --task "Найди рюкзак" --duration 150 --dry-run
```

`--dry-run` запускает настоящую модель и реальные датчики. Выход агента на моторы
отключён. Проверка завершается после одного цикла инференса. Стратегия 2 включает
генерацию и последующий выбор кандидата, поэтому ей может потребоваться больше времени.

## Остановка

В терминале запуска нажмите **Ctrl+C**. Из второго терминала можно отправить стоп.

```bash
cd /Users/double/Documents/Codex/2026-11-10/x20/outputs
./rover-qwen.sh stop --rover 107
```

Mac передаёт независимый сигнал связи. Если он пропадает примерно на две секунды,
агент на Raspberry завершает сеанс и передаёт нулевую скорость. Автоматического
возобновления движения после восстановления связи нет. Эта защита требует
работающей Raspberry. При полном зависании платы нужен физический останов.

Модель после завершения сеанса остаётся загруженной для повторного запуска.
Чтобы освободить GPU после окончания работы, выполните следующую команду.

```bash
./rover-qwen.sh model-stop
```

Просмотр можно включить или остановить отдельно.

```bash
./rover-qwen.sh view --rover 107
./rover-qwen.sh view-stop --rover 107
```

Каждый запуск печатает путь к своим журналам внутри контейнера. Там сохраняются
кадры камеры, карты, кандидаты, ответы модели и события движения. Для стратегии 2
сохраняются также исходные предложения Qwen и результаты их проверки.


Каждый запуск использует отдельный Unix-сокет на Mac для соединения с моделью.
Порт 18766 используется сервисом Qwen на сервере. Старые локальные TCP-туннели
на Mac больше не мешают повторному запуску.

Подсказки потокам наблюдения и пространственного анализа написаны на английском,
поэтому их тексты обычно приходят на английском и при русском задании. `--task`
передаёт текст задания модели, но не задаёт отдельную настройку языка анализа.


## История и выбор направления в стратегии 4

Каждое новое решение получает сводку последних восьми планов: измеренные
повороты, перемещения, отменённые шаги и направления заблокированных попыток
движения. Успешные повороты сохраняются как выполненный прогресс после отмены
последующего движения вперёд. Сводка отмечает качание в противоположные стороны
без выхода из прежнего места; это подсказка модели, а не запрет обратных поворотов.

Агент также передаёт геометрические варианты поворота и доступного движения
по текущей карте с учётом контура корпуса. Неизвестные клетки не считаются
свободными. Модель выбирает действия для входного задания; направление заранее
не фиксируется. Столкновения и потеря связи проверяются прежними средствами.

В стратегии 4 выбор действий теперь ждёт завершения пространственного разбора
(до 96 токенов при штатных настройках). Это увеличивает задержку одного решения;
стратегии 1–3 сохраняют прежний порядок работы. Изменения устанавливаются на
выбранного ровера автоматически следующей командой start.


## Кэш системного промпта на сервере

Для живых стратегий 1–4 сервер сохраняет отдельный KV/GDN-блок неизменного
системного сообщения. Первый запрос каждого варианта промпта заполняет кэш;
последующие используют его без повторного prefill этой части. Кэш общий для
сеансов, пока запущен сервис модели; перезапуск модели очищает его. Смена
системных токенов создаёт другую запись. Одновременно хранится до четырёх
вариантов; удаляется только неиспользуемый блок.

Камера, карта, задание и измеренная история остаются свежими: их блок создаётся
заново для каждого решения и освобождается после запроса. Симулятор сохраняет
прежний режим. Команду запуска на Mac менять не нужно.

В ответах модели и журналах `INFERENCE_AUDIT`/`GENERATION_AUDIT` поле `prefill`
показывает `system_prefix_cache_hit`, `system_prefix_tokens`,
`prefilled_system_tokens`, `observation_prefill_tokens` и длительности обеих
частей. При попадании в кэш `prefilled_system_tokens=0`. Для контролируемого
сравнения серверный backend поддерживает `--no-system-prefix-cache`.


## Размер контекста живого запуска

Сервис Qwen для живых стратегий 1–4 использует окно **12 288 токенов**:
до **10 240** на входное наблюдение, включая системный промпт и токены изображений,
и **2048** в запасе для анализа и генерации. Кэш системного промпта включён.
Пул KV-кэша увеличен вместе с окном. Команду запуска на Mac менять не нужно.

Стандартный запуск симулятора сохраняет окно 8192 и прежний лимит входа 6000.
Серверный backend поддерживает `--context-window 8192|12288`; штатный живой
launcher автоматически передаёт `--context-window 12288`.


## Короткие манёвры стратегии 4

F/G — вперёд 10/5 см, B/C — назад 10/5 см, L/R — 22,5°. Флаг Mac launcher `--disable-collision-protection` (только стратегия 4) отключает фильтр геометрии и программные остановки по лидару/контакту. Связь, свежесть датчиков, ограничения исполнения и остановка сеанса сохраняются. Без флага проверки перемещений включены. С флагом возможны столкновения. Для проверки без движения добавить `--dry-run`.
