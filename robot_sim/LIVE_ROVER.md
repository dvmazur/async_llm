# Qwen на физических rbm-80 и rbm-107

Агент работает в существующем ROS-контейнере `ros` на ровере. Qwen запускается
на сервере через штатный `run_candidate_llm.sh`. Локальный
`rover-qwen.sh` соединяет их двумя SSH-перенаправлениями через компьютер,
которому доступны оба хоста. Сетевые слушатели модели и перенаправления
ограничены loopback. Со стороны ровера используется временный Unix-сокет.

Живые стратегии используют `candidate_navigation_v1` (1 и 2) или
`direct_navigation_v1` (3) и системное время. Источники — реальный RGB из
MediaMTX `/cam`, `/scan`, карта `/map`, `/icp/odom` и TF от штатного ROS.
`/icp/odom` здесь вычисляется по лидару, `/odom` на rbm-80 не публикуется.
Режим завершения `task_completion` оценивает всю входную инструкцию;
принудительного завершения по видимости объекта нет. Измеренной калибровки
камеры и лидара для дальности до распознанного объекта пока нет.
Стратегии 1 и 2 используют отдельный контроллер Nav2 и шлюз команд движения.
Правила завершения и команды запуска экспериментов Gazebo сохраняются.

По умолчанию выбран №80. Флаг `--rover 107` (до или после команды)
использует SSH-алиас `rover107`, папку `/opt/rover-live-107` и сайт
`http://127.0.0.1:18771`. Все три стратегии доступны на обоих роверах.
Оба профиля по умолчанию работают без IMU, поскольку аппаратные сообщения
пока содержат нули. Для обязательной проверки IMU есть явный флаг `--imu`.
У №80 сохраняются `/opt/rover-live` и сайт `http://127.0.0.1:18770`.

При прямом движении вперёд №80 оставляет перед корпусом 10 см, дополнительно
учитывая расчётный путь торможения и положение лидара. Для поворотов действует
штатная круговая проверка.

```bash
./rover-qwen.sh --rover 107 deploy
./rover-qwen.sh --rover 107 smoke
./rover-qwen.sh --rover 107 gate-test
./rover-qwen.sh --rover 107 run --instruction 'Стой на месте.' --wall-limit 45
```

Только при явном `--imu` нужно подтвердить работу гироскопа лёгким поворотом
корпуса в первые 20 секунд. Если приходят только нули, агент завершит сеанс
со статусом `imu_unverified` без команд движения и без подмены гироскопа
одометрией.

## Запуск с компьютера

```bash
./rover-qwen.sh smoke
./rover-qwen.sh gate-test
# Когда обе GPU свободны, в первом терминале:
./rover-qwen.sh model
# После READY 127.0.0.1:18766, во втором:
./rover-qwen.sh run --instruction 'Стой на месте.' --wall-limit 45
```

Smoke поднимает CPU-ответчик на `127.0.0.1:18866` для №80 или
`127.0.0.1:18867` при явном `--imu`, проверяет реальные наблюдения
и проходит тот же протокол ответа. Даже его команда движения не может попасть
в `/cmd_vel`. `run` по умолчанию тоже работает без публикации в этот топик.
`gate-test` проверяет шлюз в отдельном ROS domain и тестовом топике без моторов.
Для физического движения пользователь в интерактивном терминале явно добавляет
`--enable-motion`. Перед первым таким запуском разместите ровер в свободной зоне,
держите его в поле зрения и будьте готовы остановить запуск через Ctrl+C.
При выключенном агенте действует штатный watchdog драйвера ровера.

Локальный шлюз принимает только ограниченные примитивы вперёд, поворот и стоп,
проверяет свежесть TF и сенсоров, блокирует движение при препятствии, недостаточном
покрытии лидара, устаревшем ответе, активной задаче Nav2 или наличии стороннего
издателя скоростей.
Штатный драйвер задаёт собственный минимальный поворот на месте, поэтому первый
физический прогон нужен для проверки реакции шасси. Одновременно возможен только
один экземпляр агента.

Логи пишутся внутри контейнера, каталог печатается перед стартом. Для
повторной установки после пересоздания контейнера используйте
`./rover-qwen.sh deploy` для №80 или `./rover-qwen.sh --rover 107 deploy` для №107.
Установка обновляет только отдельный каталог выбранного ровера.
