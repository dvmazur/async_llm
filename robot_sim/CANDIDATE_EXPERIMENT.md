# Эксперимент: geometric против qwen

Измеренные результаты завершённой серии:
[CANDIDATE_EXPERIMENT_RESULTS.md](CANDIDATE_EXPERIMENT_RESULTS.md).

`--candidate-mode geometric|qwen` выбирает генератор. По умолчанию сохранён
исходный CandidateGenerator. В обоих режимах один и тот же Qwen selector выбирает
точку, а Nav2/gateway исполняет и проверяет движение.

В qwen готовые frontier/object-кандидаты не вычисляются. Модель получает RGB,
онлайн-карту с пиксельной сеткой и областью достижимости, сенсорные объектные
гипотезы и историю. Она генерирует до восьми оригинальных позиций `(u,v)`,
направлений обзора и типов F/I/L (frontier/inspect/look). Потоки анализа камеры и
пространственного рассуждения работают параллельно в нативном AsyncLLM;
генератор читает их растущий KV/GDN cache. Оба TP-ранга синхронизированы;
heartbeat предотвращает истечение Gloo timeout при простое между эпизодами.

Грамматика ограничивает только синтаксис: поразрядные трёхзначные координаты
000..511, heading 0..7, тип F/I/L, W для окончания списка. Готовых якорей нет.
Геометрия переводит пиксели в map и отбрасывает стены, неизвестные клетки,
недостижимые точки, дубликаты и повторные неудачи. Допускается привязка к ближайшей
проходимой клетке максимум на 0.35 м без пересечения стен/неизвестного пространства.
Каждый сдвиг и отказ сохраняются. Автоматической подмены geometric-точками нет.
При пустом наборе возможны ожидание или подтверждение уже найденной близкой цели.

После генерации selector получает свежий снимок с проверенными точками.
Проверяется отсутствие большой коррекции map→odom между генерацией и выбором.
Сенсоры, карта, Nav2 и запись продолжают работать во время запросов.

## План серии до получения результатов

Семь задач × два метода × sensor seeds 29,43 = 28 эпизодов. Порядок методов
чередуется по задаче и повтору. В каждой паре одинаковы сцена, публичное задание,
seed шума, бюджеты и параметры управления. Асинхронный ROS/Gazebo не гарантирует
побитовую воспроизводимость при одинаковом seed. Сравниваются новые прогоны обоих
методов; все неудачи сохраняются.

| Задача | Особенность | Бюджет симуляции |
|---|---|---:|
| red_near | видимая цель, отвлекающий объект | 100 с |
| blue_occluded | цель за перегородкой | 350 с |
| green_long | дальний поиск, чередующиеся проходы | 650 с |
| absent_yellow | цели нет | 90 с |
| red_deadends | тупиковый карман, выход и обход | 500 с |
| blue_clutter | перегородки и дополнительные препятствия | 650 с |
| yellow_zigzag | три перегородки с чередующимися проходами | 750 с |

```bash
ROBOT_SIM_CPU=1 bash robot_sim/scripts/run_candidate_llm.sh --analysis-tokens 24 \
  > robot_sim/results/candidate_navigation/comparison_server.log 2>&1
# После READY:
python robot_sim/scripts/run_candidate_comparison.py \
  --output robot_sim/results/candidate_navigation/comparison_YYYYMMDD \
  --server-log robot_sim/results/candidate_navigation/comparison_server.log
```

Runner замораживает исходники и план в experiment.json, проверяет их при resume
и отказывается перезаписывать эпизоды. run_config.json содержит фактические seed,
бюджеты и хэши сцены/инструкции. Видео подписано методом и seed. В generations
сохраняются изображения, observation.json, response.json и validation.json.
Audit сопоставляет хэши обоих запросов с backend log и проверяет происхождение
каждой точки selector-а из валидированного Qwen-предложения.

COMPARISON.md/comparison.json содержат успех, причины завершения, путь, время,
контакты, число решений, дополнительную стоимость генерации и долю принятых точек.
`Model s/decision` — сумма сообщённых backend задержек завершённых запросов,
делённая на число решений. Она не включает очередь backend и остаток фонового
анализа после раннего ответа selector. Полное время эпизода учитывает эти затраты.
Проверяется равенство фактических конфигураций каждой пары. Приближённый SPL для
присутствующих целей использует evaluator-only полную геометрию на сетке 10 см
до зоны успеха радиусом 1.15 м; это не точный непрерывный оптимум. Политики эту
геометрию не получают. Отсутствующие цели исключены из SPL. Короткий путь при
неудаче не считается повышением эффективности. Два seed на сцену дают
предварительное сравнение, а не общую статистическую оценку надёжности.

## Дополнительная инфраструктурная пара

В исходной серии `red_deadends__qwen__s43` завершился с `nav2_unavailable`
и нулём исполненных целей. Лог Nav2 показывает потерю ответа lifecycle-сервиса
`planner_server/change_state` при запуске; навигатор не активировался.
После обнаружения этого сбоя объявлен один дополнительный повтор **обоих**
методов для `red_deadends`, seed 43, в исходном порядке, с прежними исходниками
и бюджетами. Повтор выполняется после основных 28 эпизодов, в отдельном каталоге.
Исходные результаты не заменяются. Дополнительных повторов по успешности не будет.

`repeat_candidate_infrastructure_pair.py` проверяет условие инфраструктурного
сбоя и хэши замороженных исходников, сохраняет отдельный manifest и после основной
серии собирает дополнительную пару, аудиты, графики и общий индекс 30 видео.
`FINAL.md` разделяет основные 28 результатов и два дополнительных. Их нельзя
смешивать в одну оценку как независимо заранее запланированные наблюдения.
